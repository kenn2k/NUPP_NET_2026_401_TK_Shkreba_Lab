## Опис предметної області

Інтернет-магазин — це система для представлення товарів та їх продажу покупцям через веб або мобільний інтерфейс. Каталог об’єднує товари за категоріями та зберігає їхні назви й ціни. Покупець може переглядати доступні позиції, додавати їх до кошика та оформлювати замовлення. У цьому навчальному проєкті доменна модель винесена до окремої бібліотеки `OnlineStore.Domain`.

## Лабораторна робота №2

Доменна модель реалізує класи `Product`, `Customer`, `Order` та `OrderItem`. Замовлення інкапсулює список позицій і керує ним лише через `AddItem()` та `RemoveItem()`. Оплата реалізована через інтерфейс `IPaymentMethod` з реалізаціями `CardPayment` і `BankTransferPayment`, що демонструє поліморфізм.

## Лабораторна робота №3

Для замовлень і покупців використано класи з ідентичністю, а адреса доставки реалізована як immutable `record`. `Customer` застосовує `required`, `init` та nullable властивість номера телефону. Методи замовлення застосовують `switch expression`, relational і property patterns для опису статусу, категорії суми та безкоштовної доставки.

## Лабораторна робота №4

Додано generic `InMemoryRepository<T>` для зберігання замовлень у пам'яті та 18 тестових замовлень. Консольний застосунок виконує LINQ-запити для фільтрації, сортування, групування, агрегації, перевірки умов і побудови словника витрат покупців.

## Лабораторна робота №5

Додано discount policies через `Func<decimal, decimal>`, журналювання операцій через `Action<string>` та `Predicate<Order>` для великих замовлень. Подія `OrderPaid` має двох підписників: сервіс сповіщень і сервіс логування. Окремий клас `OrderExtensions` додає методи `IsLargeOrder()` та `GetSummary()` без зміни доменного класу.

## Лабораторна робота №6

У моделі перевіряються обов'язкові значення, додатна ціна та кількість, а також допустимість змін залежно від стану замовлення. Консольний застосунок використовує `TryParse`, перехоплює стандартні винятки та демонструє, що невдала оплата не змінює статус замовлення й не викликає подію `OrderPaid`.

## Лабораторна робота №7

Для експорту використано DTO `OrderReport`, який містить ідентифікатор замовлення, покупця, суму, статус і кількість позицій. Звіти серіалізуються через `System.Text.Json` у файл, шлях до якого визначено в `appsettings.json`. Застосунок повторно зчитує JSON і обробляє помилки відсутнього та некоректного файлу без аварійного завершення.

## Лабораторна робота №8

Додано асинхронний зовнішній довідник контактів через `HttpClient` і JSONPlaceholder. Три незалежні запити запускаються паралельно через `Task.WhenAll`, мають обмеження часу через `CancellationToken` і не змінюють внутрішніх покупців чи замовлень. Базова URL-адреса API та час очікування налаштовуються в `appsettings.json`.
