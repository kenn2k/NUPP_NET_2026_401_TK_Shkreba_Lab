# Відповіді на контрольні питання

1. **Class, object** — Class це опис обʼєкта, object це конкретний екземпляр за описом
2. **state та behavior** — поточні дані об’єкта; behavior — дії, які він може виконувати
3. **Encapsulation** — приховування внутрішнього стану й керування ним через методи
4. У Order список \_items приватний, а змінити його можна лише через AddItem і RemoveItem
5. Виділення важливого контракту без деталізації конкретної реалізації
6. **Interface** — задає спільний контракт для різних класів і зменшує залежність коду від конкретної реалізації
7. **Polymorphism** — можливість працювати з різними об’єктами через один спільний тип
8. IPaymentMethod paymentMethod = new CardPayment("4242") paymentMethod = new BankTransferPayment("UA...");
9. **Inheritance** — створення нового класу на основі іншого з успадкуванням його членів
10. **Composition** — зв’язок HAS, Order містить колекцію OrderItem
11. **private, protected** — private доступний лише всередині самого класу; protected також у класах нащадках
12. Бо він дозволяє будь-кому довільно змінювати колекцію й порушувати правила доменної моделі
13. Interface доцільніший, коли не пов’язані успадкуванням класи мають виконувати один контракт, наприклад різні способи оплати
14. Неможливо повторно оплатити Order або оплатити скасоване замовлення: метод Pay() перевіряє поточний Status і викидає помилку.
